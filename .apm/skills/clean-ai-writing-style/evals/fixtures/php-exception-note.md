# PHP例外の考え方

## TypeError と ValueError

`TypeError` は、関数に渡した値の型が宣言と合っていないときに発生します。
`ValueError` は、型は合っていても値域や形式が関数の契約に合わないときに発生します。
どちらも、利用者の操作ミスというより、呼び出し側と関数側の契約がずれたことを表します。

## システム例外とドメイン例外について

ここでいうドメイン例外は、PHP標準の `DomainException` とは別の話です。
アプリケーションの業務ルールに近い例外と、インフラやSDKに近い例外があります。
この分類を意識することが品質にも関わります。

この理解を強める事例として、OpenAI PHP SDKで次の `TypeError` を見たことがあります。

```txt
TypeError: array_key_exists(): Argument #2 ($array) must be of type array, null given
```

これは外部APIから返ってきた値がSDK内部の期待と違っていたものです。
ただし、`Error` は絶対に `catch` してはいけない、という意味ではありません。
利用者から見ると、これはコードの型ミスに見える一方で、実行時の外部要因に寄っています。

| 種類 | 意味 |
|---|---|
| ドメイン例外 | 業務上の失敗 |
| システム例外 | システム上の失敗 |

このように、例外の名前が伝える意味と、アプリケーションで扱いたい意味は違います。

## 境界で例外を変換する

外部SDKや外部APIの内部例外をそのままアプリケーション全体へ流すと、呼び出し側は何を復旧できる失敗として扱えばよいか判断できません。
境界では、内部の例外をアプリケーション側の抽象度に合わせた例外へ変換します。
